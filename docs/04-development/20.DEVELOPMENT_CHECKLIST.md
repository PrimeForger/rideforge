# 1. Purpose

This checklist provides the final development validation gate for RideForge changes.

It converts the development standards into an actionable sequence:

```text
Understand
    ↓
Implement
    ↓
Format
    ↓
Test
    ↓
Validate Dependencies
    ↓
Review
    ↓
Integrate
```

The checklist is not a replacement for the detailed development documents.

It is the final verification layer that ensures those standards were applied.

---

# 2. How to Use This Checklist

Use the checklist according to the size and type of change.

```text
Small Change
→ Focused Checklist

Component Change
→ Component + Integration Checklist

Cross-Cutting Change
→ Full Checklist

Production / Release Change
→ Full Checklist + Release Validation
```

Do not mark a requirement complete merely because the code compiles.

# 62. Final Development Principle

> **A RideForge change is complete when its implementation, data, dependencies, tests, observability, documentation, and integration path have all been validated to the level required by its risk.**

The final engineering loop is:

```text
Understand
    ↓
Design
    ↓
Implement
    ↓
Test
    ↓
Integrate
    ↓
Observe
    ↓
Review
    ↓
Document
    ↓
Release
```

The checklist exists to prevent important work from being forgotten while keeping the development process proportional to the change.

The objective is not to maximize the number of checked boxes.

The objective is to ensure that every meaningful RideForge change is:

```text
Correct
Safe
Tested
Observable
Maintainable
Traceable
```
